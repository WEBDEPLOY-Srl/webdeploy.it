# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

The next site version is **2.0.0**. The public routes, English content and newsletter submission contract carry forward from 1.x.

### Added
- A two-list newsletter signup at `/newsletter`, with separately unticked consents, a self-hosted ALTCHA check, and a confirmation page excluded from search indexing and the sitemap.
- Newsletter submission and confirmation events, with the Meta `Lead` event gated on accepted marketing cookies and limited to `content_name: newsletter`.
- The approved newsletter privacy notice at `/privacy#newsletter` and newsletter links from the footer, news pages and contacts page.

### Changed
- The website now builds offline with Node built-ins from HTML templates, native CSS and browser ES modules. Shared JS/CSS assets use a build ID and in-page media and fonts use content hashes. Stable public media and social preview URLs remain available.
- Native document navigation replaces the client router and hover prefetch. The contact map now initializes on viewport proximity or focus. ALTCHA and Leaflet ship as pinned local distributions with verified checksums.
- The nginx image serves a static Content-Security-Policy and a complete 404 document. The cache-revalidated version marker supports visitors with an older tab open.
- Strict JSDoc type checks, node:test, production nginx browser tests and the full-tree npm audit replace the framework-dependent checks.
- The cookie banner uses identical Reject and Accept button styling, restores Close when reopened, keeps its measured space reserved while pending and during phone focus-hide, and removes it only when dismissed. Its privacy link remains visible at 200% page zoom. The `/newsletter` mobile view hides the site header so the form stays above the banner.
- The newsletter form waits for local ALTCHA readiness and disables human-interaction-signature collection. Returning from Listmonk resets list choices and submission state; setup failures instruct visitors to reload.
- The confirmed-page event is recorded only when the referrer origin is `https://newsletter.webdeploy.it`. The privacy notice now describes per-visit Matomo records and transactional manage-link behavior.
- The retired early-access path now redirects to `/newsletter` while preserving query parameters; the news-writer skill matches the smm campaign source contract.

## [1.46.0] - 2026-11-16

### Added
- The footer states the share capital (€10,000.00), as Italian law requires on company websites.
- Unknown URLs now get the site's own error page: the build emits `404.html` as the static fallback
  and nginx serves it with status 404.
- The Matomo opt-out on the privacy page is a Svelte component with typed, unit-tested cookie
  helpers (`$lib/utils/matomoOptOut.ts`) and an end-to-end test of the opt-out in both browsers.

### Security
- The image now sets its own complete set of response headers on every response, including redirects,
  errors, scripts, fonts and images: `Content-Security-Policy`, `X-Frame-Options`,
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` and `Cross-Origin-Opener-Policy`. Until
  now an asset location silently dropped the three headers set for the server, and only the reverse proxy
  put them back. nginx no longer announces its version.
- A Content-Security-Policy generated by SvelteKit in hash mode: only the site itself, the Matomo server,
  the OpenStreetMap tile server and, after consent, the Meta pixel hosts. Each page carries its policy in a
  `<meta>` tag and nginx sends the same policy as a header (built from the pages by
  `scripts/nginx-csp.mjs`, with `frame-ancestors 'self'` added). Inline style attributes are allowed;
  `<style>` elements and inline scripts are not.
- Playwright now fails any test during which the browser reports a Content-Security-Policy violation, on
  every page, the map, the consent choices and the Matomo opt-out.

### Changed
- The image build pins the current digest of the builder image; the old one had been removed from the registry.
- Caching is now exact: one year and `immutable` only under `/_app/immutable/`, one hour for other static
  files (the favicon, fonts and `.webp` images had no hashed names or no rule at all), `no-cache` for pages
  so a release shows at once, `no-store` for the temporary early-access redirect.
- The build writes precompressed `.gz` and `.br` files and nginx serves the `.gz` ones (`gzip_static`).
- Visitors can change their marketing choice at any time: a "Cookie settings" control in every page
  footer reopens the consent banner (focus moves into it and returns on close; Escape closes it).
  Withdrawing consent stops the Meta pixel and removes its `_fbp` and `_fbc` cookies. The banner is a
  named landmark with a real heading.
- The privacy policy now says where to change the choice (it wrongly told visitors to clear their
  cookies, although the choice is kept in local storage) and discloses that the map on the contacts
  page loads tiles from OpenStreetMap, which sees the visitor's IP address.
- The error page no longer uses a terminal panel; it shows the status, a title, a sentence and two buttons.

- Site facts (URL, names, contacts, address, analytics identifiers) live in one place,
  `$lib/config/site.ts`; the footer columns are data in `$lib/config/footer.ts`; the Matomo bootstrap moved
  from the root layout to `$lib/utils/matomo.ts`. Unit tests keep them in step with the translations and
  with the Content-Security-Policy hosts.
- The site-wide Organization structured data is built from that data and now carries a street address,
  contact points, an `@id` and the source repository as `sameAs`; the service pages embed the same
  publisher.
- The pages use `$app/state` instead of the deprecated `$app/stores`.
- The language cookie is now written with `SameSite=Lax` and, on HTTPS, `Secure`.

- The FOSDEM article is shared with a landscape 1200×630 image cut from the existing photo, without
  metadata, instead of the portrait photo.
- The global stylesheet is split into section files under `src/styles/` (imported in the original order,
  so the cascade is unchanged), and about thirty unused or re-declared rules are gone: animation, delay
  and easing helpers, border and shadow helpers that Tailwind already generates, the homepage service
  directory layout, an unused secondary call-to-action button and unused touch-target helpers. The
  built layout stylesheet shrank from 46.2 KB to 42.0 KB.

### Removed
- The nginx `/50x.html` error page, which never existed in the build.

## [1.45.0] - 2026-11-15

### Added
- ESLint (TypeScript and Svelte rules) and Prettier (tabs, single quotes) with `npm run lint` and
  `npm run format`.
- Vitest unit tests (`npm run test:unit`): translation parity between English and Italian, existence of
  every translation key used in the source (keys built with a template literal must match at least one
  existing key), sitemap completeness and well-formedness, and JSON-LD
  escaping.
- Playwright smoke tests (`npm run test:e2e`) in Firefox and Chromium against the production build:
  every sitemap page returns 200 with one `h1`, a title, a canonical link and a clean console; axe-core
  finds no serious or critical WCAG 2.0 to 2.2 A/AA violation; header menus work by keyboard and the
  mobile menu opens and closes; no request reaches Meta before consent and a refusal survives a reload.
  Third-party hosts are stubbed.
- `.woodpecker/check.yml`: a verification workflow on every push that needs no secrets,
  volumes or Docker socket: `reuse lint`, `nginx -t`, `npm ci`, lint, type check, unit tests, build,
  `npm audit --audit-level=high` and the Playwright suite in the official Playwright image. All images
  are pinned by digest.
- `ACCESSIBILITY.md`: the WCAG 2.2 AA target, how it is tested, known limits and how to report a problem.

### Fixed
- The company line on the security page used `slate-500`, below the WCAG AA contrast ratio on the page
  background; it now uses `slate-400`.

### Changed
- JSON-LD structured data is serialised by one helper (`$lib/utils/jsonLd.ts`) that escapes `<` and the
  JavaScript line separators; the site-wide Organization data is now built from an object. Output is
  semantically identical.
- `.woodpecker/.build.yml` waits for `check.yml`, so an image is only built and pushed from a commit that
  passed it, and pins its `alpine` and `curl` images by digest. It runs for pushes to `main` only; its manual trigger is removed.
- `package.json` pins `minimatch` to 11 through `overrides`: `typescript-eslint` pulled in a release with a
  moderate advisory, and `npm audit` again reports no high or moderate advisory.
- The Meta Pixel bootstrap is typed (`MetaPixel` in `app.d.ts`) instead of cast to `any`.

## [1.22.3] - 2026-08-20

### Changed
- The site now runs on a different production host. Nothing about the
  application changed: the same image, the same nginx config, the same 106
  files under `/usr/share/nginx/html`, verified byte-identical on both hosts
  before the DNS record moved. The deployment is managed separately from now
  on, so `docker-compose.prod.yml` is no longer what runs in production.
- CI **builds once and tags twice.** `docker-compose.build.yml` declared a
  second `version_tag` service that `extends: frontend` and differed only in
  its image tag; compose treats that as two builds of the same context, so
  `:latest` and `:<version>` were separate images with no guarantee of being
  the same bytes. The pipeline now builds `:<version>` and applies `:latest`
  with `docker tag`, which makes the version tag actually name what is running.
- Manual pipeline runs are pinned to `main`. Woodpecker's `manual` event
  carries no branch restriction of its own, so a hand-triggered build from any
  branch would have pushed that branch to `:latest` — the tag the live site
  pulls.

## [1.22.2] - 2026-08-13

### Fixed
- Header submenus were unreachable with the pointer: the 8px gap between a
  nav trigger and its submenu belonged to no element inside
  `.dropdown-container`, so crossing it fired the container's `mouseleave` and
  dismissed the menu before the cursor arrived. A transparent bridge
  (`.dropdown-menu::before`) now spans that gap, plus a 150ms grace period
  before closing.
- Keyboard access to the same submenus: `ArrowDown` on a trigger looked for the
  menu *inside* the button, so it never focused anything. It now opens the
  submenu and moves focus to the first item; `Escape` returns focus to the
  trigger, and moving focus out of a dropdown closes it.
- Tapping a nav trigger on a touch device at `lg` width did nothing — the
  tap's compatibility hover event opened the submenu and the click that
  followed toggled it straight back shut. Hover now opens only for non-touch
  pointers, and a press outside closes an open submenu.
